# S-01: Tauri window on the local axum server

Risk R-01 (02). Run 2026-10-30 on branch `spike/s01-s05`, macOS 26.0.1 (Apple silicon). Result: **passes on macOS;
Windows 11, Ubuntu and Fedora are not checked** (CI builds them; nobody has looked at the UI there).

## What was built (`app/`, kept for I1)

- Cargo workspace: `karbon-server` (axum, askama, rusqlite; no Tauri dependency, also runs in a browser as
  `karbon-dev-server`) and `karbon-desktop` (Tauri shell, binary `karbonfm`).
- At start the shell opens `karbonfm-demo.db` in the app data folder (schema 04 + `04_demo_seed.sql` on first open;
  refinery replaces this in I1), binds `127.0.0.1:0`, serves the router on the Tauri tokio runtime, and opens one window
  on `http://127.0.0.1:<port>/` with `WebviewUrl::External`. `tauri.conf.json` has `capabilities: []` and
  `withGlobalTauri: false`.
- Pages ported from design/ (sidebar, topbar, command palette, Carbon & Ember themes, Geist fonts):
  dashboard with a Chart.js revenue chart (`sales_summary_by_month`), customers list, New customer dialog, invoice
  INV-1048 with Print / Save as PDF.
- Customers list: paged (8 rows), filtered (all / overdue / on retainer / inactive), searched and sorted on the server;
  htmx swaps `#customer-table` and pushes the URL; the same URL without htmx renders the full page.
- Dialog: one `<dialog class="modal">` in the layout; htmx loads the body, app.js calls `showModal()`. The form posts with
  htmx; the server answers with the form and its error, or an empty body plus `HX-Trigger` (close + toast).
- 12 tests: 10 route tests in process (`server/tests/routes.rs`), money and initials unit tests; clippy `-D warnings`.

of, or click in, the real window. The window itself was checked by its window list and its print panel.

## Findings

1. **`window.print()` does nothing in WKWebView on macOS** (Tauri 2.12.5 / wry 0.57.1; tried from the page). Tauri's
   `WebviewWindow::print()` works. So the Print button POSTs `/print` and the server calls a print hook that the shell
   gives it; the page keeps no IPC. In a browser (dev server) `/print` answers 501 and the page uses `window.print()`.
   Recorded in 02 (Document/PDF generation). S-02 should use this path.
2. **WKWebView prints at the window's width**: a wide page (the dashboard) is cut off on the right; the invoice
   (max 820 px) fits. Print layouts need a fixed width that fits the page; the dashboard Print button was removed.
   Input for S-02.
3. Print must force the light palette (`@media print` in `styles/app.css`), or a dark-theme user prints light grey text.
4. Chart.js does not parse the themes' `oklch()` colours for its hover shades; `karbonColor()` converts them to rgba.
5. CSP: only the local server; the standard Alpine.js build needs `'unsafe-eval'`. The Alpine CSP build would remove it
   (option for I1). Inline `onclick` handlers from design/ became Alpine `@click`.
6. Overdue figures follow the local date. On 2026-10-30 INV-1048 (due 10-29) is overdue, so the page shows $6,514.55 at 4
   customers instead of design/'s $4,457.40 at 3 (as of 2026-10-28). Not a defect.
7. The Host and Origin checks of AP-13 were added now (a security review flagged that any web page could POST `/print`);
   the session cookie is still I1.

## Not verified

- Windows (WebView2) and Linux (WebKitGTK): build, test and bundle only, through `.github/workflows/app.yml`, not run
  yet (no push). Rendering, fonts, the dialog, the chart and print are unchecked there. R-01 stays open for them.
- A real click on the window's buttons (no input access in this session); the same code paths were driven in WKWebView.
- The PDF saved from Tauri's own print panel (the harness used the same WKWebView print API).
